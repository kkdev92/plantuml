# tools/clide_lua

[Lua](https://github.com/plantuml/clide/blob/main/LUA.md) scripts for
[clide](https://github.com/plantuml/clide), the semantic Java navigation tool.
They run inside the clide daemon, which has already loaded the project.

## check_assert_guard.lua

Checks that every `assert` in the source code is guarded by `TeaVM.a()`, so that
it is eliminated from the JavaScript generated by TeaVM (see the javadoc of
`net.sourceforge.plantuml.teavm.TeaVM#a()`).

### Forms recognized as guarded

```java
if (TeaVM.a()) assert x;      // single line

if (TeaVM.a())                // guard alone on line L-1
    assert x;                 // assert on line L
```

### Usage

1. Build clide (`ant`, which produces `clide.jar`).
2. Start the daemon on PlantUML, in the background:

   ```
   java -jar clide.jar C:\github\plantuml
   ```

   Wait for the `Daemon ready on port ...` line.
3. Run the script:

   ```
   python3 clide.py --lua tools/clide_lua/check_assert_guard.lua C:\github\plantuml
   ```

### Output

A summary line, then one `NOT GUARDED  path:line: text` line per unguarded
`assert`. `if (TeaVM.a())` guards whose next line is not an `assert` are listed
separately (`ORPHAN GUARD`).

Example (repository state on 2026-09-29):

```
237 assert(s) examined: 95 guarded inline, 65 guarded on the previous line, 77 NOT GUARDED  (86 lines ignored: comments/strings)
```

### How it works

clide's Lua has no `io`, and `search_regex` only returns the matching line. The
script therefore runs two searches (all `assert`s, then all standalone guards)
and cross-references them by line number. The result cap is raised to 10000, and
the script stops with an error if a result is still truncated.

### Limits

- An `assert` guarded by a block `if (TeaVM.a()) { ... }` is reported as not
  guarded: the script cannot see the braces. That is not the repository convention.
- The script does not know which files TeaVM actually compiles. An unguarded
  `assert` in code TeaVM never reaches (for example `argon2`) is reported anyway.
- `assert`s inside comments or strings are ignored heuristically (a `//` or an
  odd number of double quotes before the word).
